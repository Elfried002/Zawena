# 1. Objectif

Ce document définit le processus d'intégration des nouveaux clients sur Zawena Platform.

Les objectifs sont :

- offrir une expérience d'accueil cohérente ;
- accélérer la prise en main de la plateforme ;
- réduire le temps nécessaire avant la première utilisation productive ;
- garantir que toutes les configurations essentielles sont réalisées.

---

# 2. Portée

Cette procédure s'applique :

- aux nouveaux clients ;
- aux nouveaux projets ;
- aux nouveaux espaces de travail (workspace) ;
- aux migrations vers Zawena.

---

# 3. Principes

Chaque onboarding doit être :

- planifié ;
- documenté ;
- personnalisé selon le client ;
- validé avant sa clôture.

Le client doit être autonome à l'issue du processus.

---

# 4. Processus d'onboarding

```text
Signature du contrat

↓

Création du client

↓

Configuration du workspace

↓

Création des utilisateurs

↓

Configuration des accès

↓

Import des données (si applicable)

↓

Réunion de lancement (Kick-off)

↓

Formation

↓

Validation

↓

Fin de l'onboarding
```

---

# 5. Description des étapes

## 5.1 Signature du contrat

Objectif :

Confirmer officiellement le démarrage du projet.

Activités :

- validation du contrat ;
- validation des conditions commerciales ;
- confirmation du périmètre.

---

## 5.2 Création du client

Activités :

- création du compte client ;
- attribution d'un identifiant unique ;
- création du workspace.

---

## 5.3 Configuration du workspace

Configuration notamment de :

- paramètres généraux ;
- fuseau horaire ;
- langue ;
- informations de l'entreprise.

---

## 5.4 Création des utilisateurs

Création des premiers comptes :

- administrateur ;
- managers ;
- collaborateurs.

---

## 5.5 Configuration des accès

Définition :

- des rôles ;
- des permissions ;
- des accès aux modules.

Le principe du moindre privilège est appliqué.

---

## 5.6 Import des données

Lorsque nécessaire :

- import des clients ;
- import des prospects ;
- import des projets ;
- import des documents.

Les données importées sont vérifiées avant validation.

---

## 5.7 Réunion de lancement (Kick-off)

Objectifs :

- présenter le fonctionnement de Zawena ;
- rappeler les objectifs du projet ;
- présenter les interlocuteurs ;
- définir les prochaines étapes.

---

## 5.8 Formation

Présentation :

- du tableau de bord ;
- des principales fonctionnalités ;
- des bonnes pratiques.

La formation peut être réalisée en visioconférence ou en présentiel selon les besoins.

---

## 5.9 Validation

Le client confirme que :

- les accès fonctionnent ;
- les données sont correctes ;
- les utilisateurs sont opérationnels ;
- la plateforme est prête à être utilisée.

---

## 5.10 Fin de l'onboarding

L'onboarding est clôturé lorsque :

- toutes les étapes sont terminées ;
- le client est autonome ;
- les documents sont archivés.

# 7. Rôles et responsabilités

## Customer Success

- pilote l'onboarding ;
- accompagne le client ;
- coordonne les équipes.

---

## Équipe Commerciale

- transmet les informations du projet ;
- assure la transition après la vente.

---

## Équipe Technique

- configure la plateforme ;
- réalise les imports ;
- résout les problèmes techniques.

---

## Client

- fournit les informations nécessaires ;
- valide les configurations ;
- participe à la formation.

---

# 8. Critères de réussite

L'onboarding est considéré comme réussi lorsque :

- le workspace est opérationnel ;
- les utilisateurs disposent des accès appropriés ;
- les données sont correctement importées ;
- la formation est terminée ;
- le client confirme être prêt à utiliser la plateforme.

---

# 9. Bonnes pratiques

✔ Préparer l'environnement avant le Kick-off.

✔ Vérifier toutes les configurations.

✔ Utiliser une checklist d'onboarding.

✔ Former les administrateurs du client.

✔ Répondre rapidement aux premières questions.

✔ Recueillir un retour d'expérience à la fin de l'onboarding.

---

# 10. Anti-patterns

✘ Créer un compte incomplet.

✘ Oublier la configuration des permissions.

✘ Importer des données sans validation.

✘ Clôturer l'onboarding sans confirmation du client.

✘ Négliger la formation des utilisateurs.

---

# 11. Révision

Cette procédure est revue :

- après une évolution importante de la plateforme ;
- après un retour client significatif ;
- au minimum une fois par an.
