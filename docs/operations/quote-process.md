# 1. Objectif

Ce document décrit le processus de création, de validation, de suivi et de transformation des devis dans Zawena Platform.

Les objectifs sont :

- standardiser la création des devis ;
- garantir des estimations cohérentes ;
- assurer un suivi commercial efficace ;
- faciliter la transformation des devis en projets.

---

# 2. Portée

Cette procédure s'applique à tous les devis créés dans Zawena, qu'ils concernent :

- la création de sites web ;
- le développement d'applications web ;
- le développement SaaS ;
- la maintenance ;
- les prestations techniques ;
- les services de conseil.

---

# 3. Principes

Chaque devis doit être :

- basé sur un besoin qualifié ;
- documenté ;
- validé avant envoi ;
- suivi jusqu'à sa clôture.

Toute modification importante du périmètre nécessite une mise à jour du devis.

---


# 5. Description des étapes

## 5.1 Demande

Le besoin est identifié à partir :

- d'un prospect ;
- d'un client existant ;
- d'une demande de support ;
- d'une évolution de projet.

---

## 5.2 Analyse des besoins

Objectif :

Comprendre précisément :

- les fonctionnalités ;
- les contraintes ;
- les délais ;
- le budget.

---

## 5.3 Estimation

L'équipe estime :

- la charge de travail ;
- les ressources nécessaires ;
- les délais ;
- les coûts.

---

## 5.4 Rédaction

Le devis contient notamment :

- référence du devis ;
- client ;
- description des prestations ;
- planning estimatif ;
- prix ;
- taxes applicables ;
- conditions de paiement ;
- durée de validité.

---

## 5.5 Validation interne

Avant l'envoi, le devis est vérifié afin de confirmer :

- la cohérence des montants ;
- la faisabilité technique ;
- les délais proposés.

---

## 5.6 Envoi

Le devis est transmis au client.

La date d'envoi est enregistrée.

---

## 5.7 Négociation

Des ajustements peuvent être réalisés concernant :

- le périmètre ;
- les délais ;
- les modalités de paiement.

Chaque modification génère une nouvelle version du devis.

---

## 5.8 Décision

Le devis peut être :

- accepté ;
- refusé ;
- expiré.

---

## 5.9 Création du projet

Lorsqu'un devis est accepté :

- le projet est créé ;
- les informations sont transférées ;
- le processus d'onboarding démarre.

# 6. États d'un devis

| État | Description |
|------|-------------|
| Brouillon | En préparation |
| En validation | Vérification interne |
| Envoyé | Transmis au client |
| En négociation | Discussions en cours |
| Accepté | Validé par le client |
| Refusé | Refusé par le client |
| Expiré | Date de validité dépassée |
| Converti | Projet créé |

# 8. Rôles et responsabilités

## Commercial

- recueille les besoins ;
- prépare le devis ;
- assure le suivi.

---

## Chef de projet

- valide la faisabilité ;
- estime les délais.

---

## Équipe technique

- estime la charge ;
- identifie les contraintes techniques.

---

## Client

- examine le devis ;
- demande des ajustements si nécessaire ;
- accepte ou refuse la proposition.

---

# 9. Bonnes pratiques

✔ Utiliser un modèle de devis standard.

✔ Décrire clairement les prestations.

✔ Définir une durée de validité.

✔ Versionner les devis lors des modifications.

✔ Assurer un suivi régulier jusqu'à la décision du client.

---

# 10. Anti-patterns

✘ Établir un devis sans analyse préalable.

✘ Modifier un devis sans conserver l'historique.

✘ Oublier les conditions de paiement.

✘ Commencer le projet avant l'acceptation officielle.

✘ Laisser expirer un devis sans relance.

---

# 11. Révision

Cette procédure est revue :

- après une évolution du processus commercial ;
- après une évolution des modèles de devis ;
- au minimum une fois par an.
