# 1. Objectif

Ce document définit le processus commercial utilisé par Zawena Platform pour transformer un prospect en client.

Les objectifs sont :

- standardiser les activités commerciales ;
- améliorer le taux de conversion ;
- assurer un suivi cohérent des opportunités ;
- garantir une transition fluide vers l'équipe projet.

---

# 2. Portée

Cette procédure s'applique à :

- tous les prospects ;
- tous les clients potentiels ;
- toutes les offres commerciales ;
- tous les projets vendus via Zawena.

---

# 3. Principes

Le processus commercial repose sur :

- la compréhension des besoins du client ;
- une communication transparente ;
- la qualification des opportunités ;
- un suivi régulier ;
- une documentation complète dans le CRM.

---

# 4. Pipeline commercial

Tous les prospects suivent le pipeline suivant :

```text
Prospect

↓

Premier contact

↓

Qualification

↓

Analyse du besoin

↓

Proposition commerciale

↓

↓

Négociation

↓

↓

Signature

↓

↓

Onboarding client
```

# 5. Description des étapes

## 5.1 Prospect

Origines possibles :

- site web ;
- recommandation ;
- réseaux sociaux ;
- campagne marketing ;
- prospection directe ;
- partenariat.

Le prospect est enregistré dans le CRM.

---

## 5.2 Premier contact

Objectif :

Établir un premier échange.

Activités :

- prise de contact ;
- présentation de Zawena ;
- planification d'un rendez-vous si nécessaire.

---

## 5.3 Qualification

Objectif :

Déterminer si le prospect correspond à la cible.

Informations recueillies :

- activité ;
- taille de l'entreprise ;
- besoins ;
- budget ;
- délai souhaité.

---

## 5.4 Analyse du besoin

Objectif :

Comprendre précisément les attentes du client.

Résultat :

- périmètre du projet ;
- fonctionnalités attendues ;
- contraintes techniques ;
- objectifs.

---

## 5.5 Proposition commerciale

Préparation :

- estimation ;
- planning prévisionnel ;
- solution proposée.

---

## 5.6 Devis

Le devis comprend notamment :

- description des prestations ;
- prix ;
- délais ;
- conditions de paiement ;
- durée de validité.

---

## 5.7 Négociation

Échanges avec le client concernant :

- le périmètre ;
- le budget ;
- les délais ;
- les conditions contractuelles.

Toutes les modifications sont documentées.

---

## 5.8 Validation

Le client accepte officiellement la proposition.

Les documents nécessaires sont validés.

---

## 5.9 Signature

Le contrat est signé.

Le projet est créé dans la plateforme.

---

## 5.10 Transmission

Le dossier est transmis à l'équipe projet.

Les informations suivantes sont communiquées :

- contrat ;
- devis ;
- planning ;
- besoins du client ;
- interlocuteurs.

---

## 5.11 Onboarding

Le client est pris en charge selon la procédure décrite dans :

`client-onboarding.md`

# 7. Rôles et responsabilités

## Commercial

- prospecte ;
- qualifie ;
- prépare les offres ;
- négocie.

---

## Chef de projet

- prépare la prise en charge du projet ;
- valide le planning.

---

## Client

- exprime ses besoins ;
- valide la proposition ;
- signe le contrat.

---

# 8. KPI commerciaux

| KPI | Objectif |
|------|----------|
| Taux de conversion Prospect → Client | ≥ 25 % |
| Temps moyen de qualification | < 5 jours |
| Temps moyen entre devis et signature | < 15 jours |
| Taux d'acceptation des devis | ≥ 60 % |
| Opportunités perdues documentées | 100 % |

---

# 9. Bonnes pratiques

✔ Documenter tous les échanges dans le CRM.

✔ Qualifier les prospects avant d'établir un devis.

✔ Adapter la proposition aux besoins réels du client.

✔ Assurer un suivi régulier.

✔ Préparer une transition complète vers l'équipe projet.

---

# 10. Anti-patterns

✘ Envoyer un devis sans comprendre le besoin.

✘ Négliger le suivi d'un prospect.

✘ Modifier le périmètre sans mise à jour du devis.

✘ Promettre des fonctionnalités non validées.

✘ Transmettre un dossier incomplet.

---

# 11. Révision

Cette procédure est revue :

- après une évolution du processus commercial ;
- après une évolution du CRM ;
- au minimum une fois par an.
