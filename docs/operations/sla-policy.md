# 1. Objectif

Cette politique définit les engagements de niveau de service (SLA) proposés par Zawena Platform.

Elle permet :

- de définir les attentes des clients ;
- de standardiser le support ;
- de mesurer la qualité de service ;
- d'améliorer continuellement les opérations.

---

# 2. Portée

Cette politique couvre :

- l'application web ;
- les API ;
- l'authentification ;
- les tableaux de bord ;
- les notifications ;
- les services de support.

---

# 3. Définitions

## SLA (Service Level Agreement)

Engagement contractuel entre Zawena et ses clients.

---

## SLO (Service Level Objective)

Objectif interne mesurable permettant d'atteindre le SLA.

---

## SLI (Service Level Indicator)

Indicateur mesurant la qualité réelle du service.

Exemples :

- disponibilité ;
- temps de réponse ;
- taux d'erreur.

---

# 4. Disponibilité du service

Objectif de disponibilité :

| Service | Disponibilité cible |
|----------|--------------------:|
| Plateforme Web | 99,9 % |
| API | 99,9 % |
| Authentification | 99,9 % |

Les interruptions dues à une maintenance planifiée ne sont pas prises en compte dans le calcul du SLA.

---

# 5. Niveaux de support

| Niveau | Description |
|---------|-------------|
| Standard | Support de base |
| Premium | Priorité renforcée |
| Enterprise | Support prioritaire et suivi personnalisé |

Les modalités commerciales de chaque niveau sont précisées dans les offres de service.

---

# 6. Priorités des incidents

| Priorité | Description |
|-----------|-------------|
| P1 | Service indisponible ou incident critique |
| P2 | Fonctionnalité majeure dégradée |
| P3 | Dysfonctionnement mineur |
| P4 | Demande d'information ou amélioration |

---

# 7. Temps de réponse et de résolution

| Priorité | Première réponse | Objectif de résolution |
|-----------|-----------------:|-----------------------:|
| P1 | < 1 heure | < 4 heures |
| P2 | < 4 heures | < 1 jour ouvré |
| P3 | < 1 jour ouvré | < 5 jours ouvrés |
| P4 | < 2 jours ouvrés | Selon planification |

Ces objectifs constituent des cibles opérationnelles et peuvent évoluer avec la maturité du service.

---

# 8. Maintenance planifiée

Les opérations de maintenance sont :

- planifiées à l'avance ;
- communiquées aux clients lorsque nécessaire ;
- réalisées autant que possible en dehors des heures de forte utilisation.

Les maintenances d'urgence peuvent être effectuées sans préavis si elles sont nécessaires pour préserver la sécurité ou la disponibilité du service.

---

# 9. Responsabilités

## Zawena

- maintenir la plateforme ;
- assurer le support ;
- communiquer sur les incidents majeurs ;
- suivre les indicateurs de performance.

---

## Client

Le client est responsable :

- de la sécurité de ses identifiants ;
- de la qualité des informations transmises au support ;
- du respect des conditions d'utilisation.

---

# 10. Mesure des performances

Les principaux indicateurs suivis sont :

- disponibilité du service ;
- temps moyen de réponse (MTTA) ;
- temps moyen de résolution (MTTR) ;
- nombre d'incidents ;
- respect des SLA.

Les résultats sont utilisés pour améliorer les opérations.

---

# 11. Bonnes pratiques

✔ Mesurer régulièrement les indicateurs de service.

✔ Informer rapidement les clients en cas d'incident majeur.

✔ Documenter chaque incident important.

✔ Réviser les SLA en fonction de l'évolution du produit.

---

# 12. Révision

Cette politique est revue :

- une fois par an ;
- après une évolution majeure des services ;
- après une modification importante des offres commerciales.
