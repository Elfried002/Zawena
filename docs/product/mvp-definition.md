# 1. Objectif

Ce document définit le périmètre du Minimum Viable Product (MVP) de Zawena Platform.

Il précise les fonctionnalités indispensables à la première mise en production et distingue clairement les évolutions prévues pour les versions futures.

Le MVP doit permettre :

- de démontrer la valeur du produit ;
- d'obtenir les premiers clients ;
- de valider les hypothèses métier ;
- de recueillir des retours utilisateurs ;
- de préparer les évolutions futures.

---

# 2. Définition du MVP

Le MVP de Zawena est une plateforme SaaS permettant à une agence digitale ou une ESN de gérer l'ensemble de son cycle commercial et opérationnel.

Le périmètre couvre :

- acquisition de prospects ;
- gestion commerciale ;
- gestion des projets ;
- collaboration interne ;
- portail client ;
- gestion des contenus ;
- administration.

Le MVP est conçu pour être directement exploitable dans un contexte réel.

---

# 3. Vision du MVP

À l'issue du développement, un utilisateur doit pouvoir :

- découvrir Zawena via le site web ;
- envoyer une demande de contact ou de devis ;
- être enregistré dans le CRM ;
- recevoir un devis ;
- accepter ce devis ;
- voir un projet créé automatiquement ;
- suivre l'avancement du projet ;
- consulter les livrables ;
- communiquer avec l'équipe ;
- administrer entièrement la plateforme.

---

# 4. Objectifs

## Objectifs métier

- Digitaliser les processus commerciaux.
- Réduire le temps de traitement des devis.
- Centraliser les données clients.
- Simplifier la gestion des projets.
- Améliorer la collaboration avec les clients.

## Objectifs techniques

- Architecture modulaire.
- Déploiement cloud.
- Interface responsive.
- API REST documentée.
- Authentification sécurisée.

# 8. Critères de succès

Le MVP sera considéré comme réussi lorsque :

- Un prospect peut devenir client sans intervention manuelle.
- Un devis accepté crée automatiquement un projet.
- Un client peut suivre son projet.
- Les utilisateurs peuvent collaborer efficacement.
- Les contenus du site sont administrables.
- Les administrateurs peuvent gérer entièrement la plateforme.

---

# 9. Contraintes

## Techniques

- Architecture cloud.
- Responsive Design.
- API REST.
- Authentification sécurisée.

## Métier

- Respect du workflow commercial.
- Gestion des permissions par rôle.
- Traçabilité des actions.

---

# 10. Hypothèses

- Les utilisateurs disposent d'une connexion Internet.
- Les notifications email sont opérationnelles.
- Les données sont hébergées dans une base sécurisée.
- Les administrateurs configurent correctement la plateforme.

---

# 11. Risques

- Évolution du périmètre (Scope Creep).
- Complexité des workflows.
- Retards de développement.
- Dépendance à des services tiers.
- Adoption utilisateur plus lente que prévue.
