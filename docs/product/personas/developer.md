# 1. Objectif

Le Développeur est responsable de la conception, du développement, des tests, de la maintenance et de l'amélioration des produits logiciels de Zawena.

Il transforme les besoins métier en fonctionnalités fiables, sécurisées et évolutives.

# 3. Profil

Le Développeur maîtrise :

- le développement logiciel ;
- Git ;
- les API ;
- les bases de données ;
- les bonnes pratiques de sécurité ;
- les outils collaboratifs.

Il travaille quotidiennement avec :

- le Chef de Projet ;
- les Administrateurs ;
- les Designers ;
- les Agents IA.

---

# 4. Responsabilités

Le Développeur est responsable de :

- développer les fonctionnalités ;
- corriger les anomalies ;
- effectuer les revues de code ;
- écrire les tests ;
- maintenir la documentation technique ;
- participer aux déploiements ;
- améliorer les performances ;
- respecter les standards de développement.

---

# 5. Objectifs métier

Le Développeur cherche à :

- livrer des fonctionnalités de qualité ;
- limiter la dette technique ;
- maintenir une couverture de tests élevée ;
- produire un code lisible ;
- garantir la sécurité des développements.

# 12. Actions critiques

Le Développeur peut :

- créer une branche ;
- fusionner une Pull Request (selon les règles définies) ;
- exécuter une migration ;
- déployer en préproduction ;
- corriger un bug critique.

Toutes ces opérations sont journalisées.

---

# 13. Permissions

Le Développeur peut :

✓ consulter les projets ;

✓ modifier le code source ;

✓ exécuter les tests ;

✓ créer des migrations ;

✓ consulter les journaux applicatifs ;

✓ accéder aux environnements autorisés.

---

# 14. Restrictions

Le Développeur ne peut pas :

✗ modifier les rôles ;

✗ gérer les utilisateurs ;

✗ supprimer des sauvegardes ;

✗ accéder aux secrets de production sans autorisation ;

✗ modifier les paramètres globaux.

# 16. Standards de développement

Le Développeur respecte :

- les conventions de nommage ;
- le Design System ;
- les règles Git ;
- les standards de sécurité ;
- les principes SOLID lorsque pertinents ;
- la documentation obligatoire.

Toute fonctionnalité doit être documentée avant sa mise en production.

# 17. KPIs

Le Développeur est évalué notamment sur :

- qualité du code ;
- nombre de bugs critiques ;
- temps moyen de résolution ;
- couverture des tests ;
- respect des délais ;
- stabilité des livraisons.

# 18. Risques

Les principaux risques sont :

- régression ;
- dette technique ;
- faille de sécurité ;
- perte de performances ;
- indisponibilité du service.

Les changements sensibles doivent être validés avant leur déploiement.
