# 1. Objectif

Ce document définit le format officiel des études de cas publiées par Zawena.

Les objectifs sont :

- démontrer la valeur de la plateforme ;
- partager des résultats concrets ;
- renforcer la crédibilité de Zawena ;
- faciliter les démarches commerciales ;
- produire des contenus marketing réutilisables.

---

# 2. Vision

Chaque étude de cas doit raconter une histoire réelle.

Elle ne doit pas seulement présenter une fonctionnalité mais montrer :

- le problème rencontré ;
- la solution mise en œuvre ;
- les résultats obtenus ;
- les enseignements tirés.

Les études de cas doivent être basées sur des données vérifiables et, lorsque cela est possible, validées par le client.

---

# 3. Quand créer une étude de cas ?

Une étude de cas peut être réalisée lorsqu'un projet présente un intérêt particulier, par exemple :

- un projet représentatif ;
- une amélioration significative des performances ;
- une transformation réussie des processus ;
- une utilisation innovante de la plateforme ;
- un retour d'expérience particulièrement positif.

Le consentement du client est obtenu avant toute publication mentionnant son identité ou des informations confidentielles.

---

# 4. Structure standard

Chaque étude de cas suit la structure suivante :

## Présentation du client

- secteur d'activité ;
- taille de l'organisation ;
- contexte général.

---

## Situation initiale

Description des problématiques rencontrées avant l'utilisation de Zawena.

---

## Objectifs

Présentation des objectifs définis avec le client.

---

## Solution mise en œuvre

Description :

- modules utilisés ;
- fonctionnalités déployées ;
- accompagnement réalisé ;
- durée du projet.

---

## Résultats

Présentation des résultats obtenus.

Lorsque cela est possible, utiliser des indicateurs mesurables.

Exemples :

- réduction du temps de traitement ;
- augmentation du nombre de projets suivis ;
- amélioration du taux de satisfaction ;
- diminution des erreurs ;
- meilleure visibilité sur les activités.

---

## Témoignage

Citation du client (avec son autorisation).

---

## Enseignements

Retour d'expérience de l'équipe projet :

- points positifs ;
- difficultés rencontrées ;
- améliorations identifiées.

# 6. Bonnes pratiques

✔ Utiliser des données réelles et vérifiables.

✔ Mettre en avant les bénéfices métier.

✔ Illustrer les résultats avec des chiffres lorsque cela est possible.

✔ Employer un langage clair et accessible.

✔ Obtenir l'autorisation du client avant publication.

✔ Réutiliser les études de cas dans les présentations commerciales, le site web et les campagnes marketing.

---

# 7. Anti-patterns

✘ Exagérer les résultats.

✘ Publier des informations confidentielles.

✘ Utiliser des données non vérifiées.

✘ Se concentrer uniquement sur les fonctionnalités sans expliquer leur impact.

✘ Oublier de mesurer les résultats.
