# 1. Objectif

Ce document centralise toutes les idées d'évolution de Zawena Platform.

Les objectifs sont :

- conserver les idées avant leur évaluation ;
- éviter la perte d'opportunités ;
- structurer l'innovation produit ;
- faciliter la priorisation ;
- alimenter la roadmap.

Une idée documentée n'implique pas qu'elle sera développée.

---

# 2. Vision

Les meilleures idées ne viennent pas uniquement de l'équipe Produit.

Elles peuvent provenir :

- des clients ;
- des utilisateurs ;
- des équipes commerciales ;
- du support ;
- de la veille concurrentielle ;
- des expérimentations ;
- des avancées technologiques ;
- de l'intelligence artificielle.

Chaque idée est analysée selon sa valeur métier avant toute décision.

---

## Titre

Nom de l'idée.

---

## Auteur

Personne ou équipe à l'origine de l'idée.

---

## Date

Date de création.

---

## Catégorie

Exemple :

- IA
- Produit
- UX

- Infrastructure

Présentation de l'idée.

---

## Problème identifié

Quel problème cette idée cherche-t-elle à résoudre ?

---

## Solution proposée

Description de la solution envisagée.

---

## Valeur métier

---

## Impact utilisateur

---

## Effort estimé

- Faible
- Moyen
- Élevé

---

## Priorité

- Faible
- Moyenne
- Haute
- Critique

## Dépendances

## Décision

- Rejetée
- Reportée
- À étudier

# 7. Critères de priorisation

Chaque idée est évaluée selon plusieurs critères.

| Critère | Description |
|----------|-------------|
| Valeur métier | Impact pour les clients |
| Valeur utilisateur | Amélioration de l'expérience |
| Alignement stratégique | Cohérence avec la vision |
| Complexité | Effort de développement |
| Risques | Techniques, juridiques, opérationnels |
| Coût | Ressources nécessaires |
| Urgence | Besoin immédiat ou futur |

Lorsque cela est pertinent, une méthode de priorisation (par exemple RICE, ICE ou MoSCoW) peut être utilisée.

# 9. Gouvernance

La revue des idées est réalisée régulièrement par l'équipe Produit.

Les décisions prennent notamment en compte :

- les besoins clients ;
- les données d'utilisation ;
- les objectifs stratégiques ;
- les contraintes techniques ;
- les ressources disponibles.

Les idées retenues alimentent la roadmap officielle.

---

# 10. Bonnes pratiques

✔ Documenter toutes les idées, même les plus simples.

✔ Décrire le problème avant la solution.

✔ Prioriser selon la valeur apportée.

✔ Réévaluer régulièrement les idées anciennes.

✔ Utiliser des données pour orienter les décisions.

✔ Relier les idées aux retours clients lorsque cela est possible.

---

# 11. Anti-patterns

✘ Développer une idée sans validation.

✘ Prioriser uniquement selon l'intuition.

✘ Ignorer les contraintes techniques.

✘ Supprimer les idées rejetées sans conserver leur historique.

✘ Confondre une idée avec une exigence produit.

---

# 12. Révision

Ce document est revu :

- lors de chaque revue produit ;
- avant chaque planification de roadmap ;
- après une évolution majeure du marché ;
- au minimum une fois par trimestre.
