# 1. Objectif

Ce document définit les règles de rédaction officielles de Zawena.

Il garantit une communication claire, cohérente et professionnelle sur tous les supports :

- site internet ;
- applications ;
- documentation ;
- emails ;
- réseaux sociaux ;
- supports marketing ;
- présentations.

Tous les contenus publiés au nom de Zawena doivent respecter ces règles.

---

# 2. Principes de rédaction

Nos contenus doivent être :

- clairs ;
- simples ;
- précis ;
- utiles ;
- cohérents ;
- orientés vers les besoins du lecteur.

Chaque phrase doit avoir un objectif.

Nous supprimons toute information inutile.

---

# 3. Structure des contenus

Chaque contenu suit une structure logique.

## Introduction

Présenter le sujet.

---

## Développement

Expliquer.

Illustrer.

Apporter de la valeur.

---

## Conclusion

Résumer.

Proposer une action lorsque cela est pertinent.

---

Les paragraphes doivent rester courts.

Une idée principale par paragraphe.

---

# 4. Style rédactionnel

Nous privilégions :

- les phrases courtes ;
- les verbes d'action ;
- les formulations positives ;
- les exemples concrets.

Nous évitons :

- les formulations vagues ;
- les répétitions ;
- le jargon inutile ;
- les superlatifs excessifs.

---

# 5. Terminologie officielle

Les termes suivants sont utilisés de manière cohérente.

## Intelligence Artificielle

Toujours avec les majuscules.

---

## IA

Autorisé après la première occurrence.

---

## SaaS

Toujours écrit en majuscules.

---

## API

Toujours écrit en majuscules.

---

## Tableau de bord

Préférer cette expression à « dashboard » dans les contenus en français.

---

## Site web

Préférer « site web » à « website ».

---

## Application

Utiliser « application » plutôt que « app » dans les contenus institutionnels.

---

## Client

Employer « client » plutôt que « utilisateur » lorsque le contexte est commercial.

---

# 6. Règles typographiques

Respecter les conventions françaises.

- espace avant « : », « ; », « ? » et « ! » ;
- guillemets français (« ») lorsque cela est pertinent ;
- une seule espace entre les mots ;
- pas de double ponctuation.

Les titres utilisent une casse cohérente.

Éviter les MAJUSCULES inutiles.

---

# 7. Rédaction des interfaces

Les textes affichés dans les applications doivent être :

- courts ;
- explicites ;
- orientés action.

### Boutons

Privilégier des verbes.

Exemples :

- Créer
- Enregistrer
- Envoyer
- Modifier
- Supprimer
- Télécharger

---

### Messages de confirmation

Toujours indiquer le résultat.

Exemple :

Votre demande de devis a été envoyée avec succès.

---

### Messages d'erreur

Toujours expliquer le problème.

Toujours proposer une solution.

Exemple :

Impossible d'enregistrer les modifications.

Veuillez vérifier votre connexion Internet puis réessayer.

---

### Formulaires

Les labels doivent être explicites.

Exemple :

Adresse email

plutôt que

Email

# 8. Rédaction des emails

Chaque email suit la structure suivante.

- Objet clair.
- Salutation.
- Contexte.
- Informations principales.
- Appel à l'action.
- Signature.

Les emails doivent rester concis.

---

# 9. Rédaction du site web

Chaque page répond à trois questions.

Que proposons-nous ?

À qui s'adresse cette solution ?

Pourquoi choisir Zawena ?

Les appels à l'action doivent être visibles et orientés bénéfice.

Exemples :

- Demander un devis
- Planifier un échange
- Découvrir nos services
- Commencer un projet

---

# 10. Rédaction des réseaux sociaux

Les publications doivent :

- apporter de la valeur ;
- rester professionnelles ;
- encourager la discussion ;
- refléter l'expertise de Zawena.

Éviter les formulations sensationnalistes.

Privilégier les retours d'expérience, les conseils et les études de cas.

---

# 11. Rédaction de la documentation

La documentation doit être :

- structurée ;
- versionnée ;
- précise ;
- durable.

Chaque document comprend :

- un objectif ;
- une table des matières ;
- un contenu organisé ;
- des références.

Les décisions importantes doivent être documentées.

---

# 12. Bonnes pratiques

Toujours :

- relire les contenus avant publication ;
- vérifier les informations techniques ;
- respecter la charte graphique ;
- adapter le niveau de langage au public visé.

Privilégier les bénéfices pour le lecteur plutôt que les caractéristiques techniques.

---

# 13. À éviter

Ne jamais :

- exagérer les performances ;
- utiliser des promesses impossibles à tenir ;
- employer un ton agressif ;
- publier des informations non vérifiées ;
- multiplier les acronymes sans explication.

Chaque contenu doit renforcer la crédibilité de Zawena.
